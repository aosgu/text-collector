| 日期 | 版本 | 变更摘要 |

### v1.0.1 实际落地修订

1. **侧边栏默认宽度调整为 300px**：`manager/todo.css` 中 `.todo-sidebar` 保持 `flex-shrink: 0`，因此在可用桌面空间内维持 300px，不被弹性压缩。
2. **添加事项输入框改为稳定基准、按内容扩展**：`.todo-add-form input` 从 `flex: 1` 调整为 `flex: 0 1 480px` + `width: 480px` + `min-width: 0`。右侧内容区允许收缩且内层最大宽度为 960px，为可见扩展保留空间；在窄容器中保留收缩行为；窗口扩宽时只恢复至 480px 基准、不消耗额外空白；`manager/todo.js` 的 `resizeAddItemInput` 以 canvas 测量实际文本，只有超过 480px 时才同步调高 `width` 与 `flex-basis`，提交后清空并恢复基准。添加按钮固定为 `flex: 0 0 28px`，不会被长文本挤压变形。
3. **数据与工作流不变**：清单/事项/模板的存储模型、Enter 提交、创建事项后的重渲染、hash 路由及待办交互均未变化。

### v1.0-draft → v1.0.0 实际落地修订

1. **页面入口从独立 `todo.html` 改为同页 Tab 切换**：旧版 §1 / §6.1 / §6.2 中"待办 = 整页替换"的设计**被回退**。v1.0.0 实际是在 `manager.html` 同页内 hash 路由切换采集/待办；`todo/` 子目录已被删除（`utils/todo-storage.js` / `manager/todo.js` / `manager/todo.css` 取代了 `todo/todo.html` / `todo/todo.css`）。
2. **URL 状态从 query string 改为 hash 段**：旧版 §1.3 / §6.2 / §7.2 中 `?view=list&id=xxx` 改为 `#todo/list/<id>` / `#todo/all` / `#todo/done` / `#todo/templates` / `#todo`（hash 路由，浏览器后退/前进可穿梭）。
3. **清单不暴露拖拽/↑↓ UI**：旧版 §3.1 中"拖拽侧边栏列表项"**未实现**——清单仅按 `order` 字段排序，零 UI 入口；`utils/todo-storage.js` 中 `reorderLists` 函数**不导出**给 todo.js。
4. **待办项仅未完成项可拖拽**：旧版 §3.2 "拖拽排序"对已完成项同样适用被细化——**已完成项拖拽被拒绝**（无拖拽手柄）。
5. **删除事项去掉了 5s 撤销 toast**：旧版 §3.2 "直接删除（无确认），显示撤销 toast" 落地为「直接删除，无二次确认，无撤销」（待办项是低破坏操作，撤销会让用户对"删除"产生犹豫）。
6. **工作台进度改为「X / Y」纯文字**：旧版 §4.1 / §5.5 中"进度条 71%" 改为「3 / 8」纯文字，**无 `<progress>` 元素、无自定义进度条**。
7. **模板管理去掉了"重命名"和"复制模板"操作**：旧版 §3.3 中"重命名模板" / "复制模板（副本）"**未实现**——模板库仅支持「使用该模板」「复制到当前清单」「删除」三个动作。
8. **「+ 添加待办」按钮改为常驻输入框**：旧版 §3.2 "点击 + 添加待办 → 列表底部插入空输入框" 改为「工作台顶部常驻输入框 + Enter 提交」——减少点击步骤。
9. **删除清单入口只在工作台顶部**：旧版 §3.1 "悬停清单项 → 显示删除按钮" 改为「仅工作台顶部的"删除清单"按钮可删清单」——侧边栏无删除入口，避免误删。
10. **"复制到当前清单"动作需先在工作台视图**：旧版 §3.3 隐含"任意视图可复制到当前清单"被收窄——`onCopyTemplateToCurrentList` 要求 `currentList` 存在。
11. **事项内容长度上限 5000 字符**（与采集一致）。
12. **空清单不能存为模板**：`onSaveAsTemplate` 先检查 `items.length > 0`，否则 toast 拒绝。
13. **4 视图切换入口改为侧边栏底部导航 + URL hash 双通路**：旧版 §3.4 仅有侧边栏入口，落地为「侧边栏底部 3 按钮（全部待办/已完成/模板库）+ hash 路由直接定位」。

## 2. 数据模型

### 2.1 TodoList（清单）

```javascript
{
  id: string,           // UUID v4
  name: string,         // 清单名称
  createdAt: number,    // 创建时间戳
  updatedAt: number,    // 更新时间戳
  order: number,        // 排序权重（越小越靠前）
  itemCount: number,    // 待办数量（缓存）
  completedCount: number // 已完成数量（缓存）
}
```

### 2.2 TodoItem（待办事项）

```javascript
{
  id: string,           // UUID v4
  listId: string,       // 所属清单 ID
  content: string,      // 内容文本
  completed: boolean,   // 完成状态
  order: number,        // 排序权重（越小越靠前）
  createdAt: number,    // 创建时间戳
  completedAt: number | null  // 完成时间戳
}
```

### 2.3 Template（模板）

```javascript
{
  id: string,           // UUID v4
  name: string,         // 模板名称
  items: string[],      // 事项内容数组（不含状态）
  createdAt: number,    // 创建时间戳
  updatedAt: number     // 更新时间戳
}
```

### 2.4 存储键设计

| 数据 | 存储键 | 说明 |
|------|--------|------|
| 清单列表 | `todo_lists` | TodoList[] |
| 待办事项 | `todo_item_<id>` | 单个 TodoItem |
| 模板列表 | `todo_templates` | Template[] |
| 视图状态 | URL 参数 | 通过 URL 管理 |

## 3. 交互设计

### 3.1 清单管理

| 操作 | 触发 | 系统行为 |
|------|------|----------|
| 创建空白清单 | 点击"+ 新建清单" | 立即创建"未命名清单"，进入工作台 |
| 重命名清单 | 点击清单标题 | 进入编辑状态，回车保存 |
| 删除清单 | 悬停显示删除按钮 → 点击 | 二次确认弹窗 → 删除清单及所有待办 |
| 排序清单 | 拖拽侧边栏列表项 | 实时更新排序 |

### 3.2 待办事项管理

| 操作 | 触发 | 系统行为 |
|------|------|----------|
| 添加待办 | 点击"+ 添加待办" | 列表底部插入空输入框，聚焦，Enter 保存 |
| 编辑内容 | 点击内容文本 | 进入编辑状态，回车保存，Esc 取消 |
| 完成事项 | 点击勾选控件 | 切换 completed 状态，完成的沉底 |
| 删除事项 | 悬停显示删除按钮 → 点击 | 直接删除（无确认），显示撤销 toast |
| 拖拽排序 | 拖拽事项 | 实时更新 order，完成的事项不参与拖拽 |

### 3.3 模板管理

| 操作 | 触发 | 系统行为 |
|------|------|----------|
| 存为模板 | 点击"存为模板"按钮 | 使用清单名称创建模板，复制所有事项内容 |
| 使用模板 | 悬停卡片 → 点击"使用该模板" | 创建同名新清单，复制事项为未完成 |
| 复制模板 | 模板详情区"复制模板"按钮 | 创建模板副本，名称加"（副本）" |
| 删除模板 | 悬停显示删除按钮 → 点击 | 二次确认弹窗 → 删除 |
| 重命名模板 | 点击模板名称 | 进入编辑状态，回车保存 |

### 3.4 视图切换

| 操作 | 触发 | 系统行为 |
|------|------|----------|
| 进入清单 | 点击侧边栏清单项 | 显示清单工作台 |
| 全部待办 | 点击侧边栏"全部待办" | 显示所有未完成事项汇总 |
| 已完成 | 点击侧边栏"已完成" | 显示所有已完成事项汇总 |
| 模板库 | 点击侧边栏"模板库" | 显示模板卡片列表 |

## 6. 技术实现

### 6.1 文件结构

```
text-collector/
├── todo/
│   ├── todo.html          # 待办页面入口
│   ├── todo.css           # 待办页面样式
│   ├── todo.js            # 待办页面逻辑
│   ├── todo-storage.js    # 待办数据操作
│   └── todo-render.js     # 待办渲染函数
├── utils/
│   └── storage.js         # 已有采集存储（不修改）
└── manifest.json          # 更新权限
```

### 6.2 页面入口

- 顶部"待办"按钮 → 打开 `todo/todo.html`（整页替换）
- URL 参数管理视图状态

### 6.3 样式复用

复用 `manager.css` 的 CSS 变量和组件样式：
- 按钮 `.btn` / `.btn-primary` / `.btn-danger`
- 卡片 `.card`
- Toast 通知
- 弹窗 `.modal-overlay` / `.modal`
- 颜色变量 `--blue` / `--text` / `--border` 等
- 字体 `--serif` / `--sans`

### 6.4 数据隔离

- 待办数据使用独立存储键（`todo_` 前缀）
- 与采集记录完全隔离
- 使用 `chrome.storage.local` 的 `todo_lists` / `todo_items` / `todo_templates`

## 7. 状态管理

### 7.1 应用状态

```javascript
{
  currentView: 'list' | 'all' | 'done' | 'templates',
  currentListId: string | null,
  lists: TodoList[],
  items: Map<string, TodoItem>,
  templates: Template[],
  isLoading: boolean
}
```

### 7.2 URL 状态

| URL | 视图 |
|-----|------|
| `?view=list&id=xxx` | 清单工作台 |
| `?view=all` | 全部待办 |
| `?view=done` | 已完成 |
| `?view=templates` | 模板库 |

## 8. 边界情况

| 场景 | 处理方式 |
|------|----------|
| 删除清单 | 二次确认弹窗，包含清单名称 |
| 删除模板 | 二次确认弹窗 |
| 空清单 | 显示"暂无待办事项，添加一条吧" |
| 空模板库 | 显示"还没有模板，从清单存为模板开始" |
| 删除最后一个事项 | 清单保留，显示空状态 |
| 使用同名模板 | 允许，创建同名清单（用户可后续重命名） |
| 事项内容为空 | 拒绝保存，自动移除空事项 |
